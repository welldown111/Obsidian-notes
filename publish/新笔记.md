一开始创建新仓库的时候，弄git，得用ssh的，用http协议的话之后干啥都可能出问题。
git branch -M main不是新建一个分支，而是将当前分支重命名为main
在git init之后得应该就已经有分支了叫master。
-M是rename的意思

git remote add origin https://github.com/welldown111/Obsidian-notes.git
这个的目的是让本地git仓库绑定一个远程仓库的别名
这个别名就是设置的origin，也可以设置别的，他就代表一个远程仓库了，不是分支
add就是添加这样一个本地与远程的连接，所以显然一个本地仓库可以连接到不同的远程仓库
后面的xxx.git就是远程仓库的真实地址，origin代表他是他的别名

git@github.com:welldown111/Obsidian-notes.git
这个可以替代上面的http，用ssh协议。注意！
如果前面创建连接是http，之后访问远程仓库走的就都是http协议，在国内显然经常受到影响
之后push和pull都走的是http或者ssh

要验证当前关联的远程仓库的通信协议直接看远程仓库地址即可
```
git remote -v
```

如果之前创建的是http的想切到ssh
```
# 替换远程 origin 的地址为 SSH 格式
git remote set-url origin git@github.com:welldown111/Obsidian-notes.git
```
直接修改现有的origin的对应的地址。
也可以先删除origin这个变量名，重新添加一下就好了
```
# 1. 删除原有的 HTTPS 地址
git remote remove origin

# 2. 重新添加 SSH 地址
git remote add origin git@github.com:welldown111/Obsidian-notes.git
```


```
git push -u origin main
```
把本地 main 分支推送到远程 origin 仓库
push：将本地分支的提交推送到远程仓库；
-u 是--set-upstream的缩写，作用是建立本地 main 分支和远程 origin/main 分支的 “追踪关系”；
- 建立后，后续只需执行 git push/git pull，无需再写 origin main，Git 会自动匹配对应的远程分支；

当本地开了新的分支，远端如何处理：
```
# 1. 本地新建并切换到 new 分支
git checkout -b new  # 等价于 git branch new + git checkout new

# 2. 做一些修改并提交
git add .
git commit -m "新分支的第一次提交"

# 3. 首次推送到远程（必须指定 origin 和分支名，-u 建立追踪）
git push -u origin new

# 后续就简单正常push，已经建立了连接。
# 修改文件后提交
git add .
git commit -m "后续提交"

# 直接 push 即可，Git 会自动推到 origin/new
git push
```


-u是建立本地分支与远程仓库的追踪关系
如果开了新分支，直接git push origin new的话
后续单纯些git push会报错，只能再次指定好origin和new。
补救方法是：
```
# 给本地 new 分支绑定远程 origin/new 分支
git branch --set-upstream-to=origin/new new
```
